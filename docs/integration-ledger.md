## Source decisions

“Implemented” means working code with the validation stated here, not physical-phone certification. Source implementations were read and ported selectively into one service/history/export/library. Large competing services, settings stores and players were replaced together to avoid carrying mutually incompatible state models.

## Concrete remaining source blockers

These are unfinished consolidation experiments, separate from the empty custom-feature backlog. No dummy control or success path ships.

| Feature | Source evidence | Required work before enabling |
| --- | --- | --- |
| Simultaneous microphone + device stereo | Mike master `MultiSourceAudioRecorder` and the Copilot branch contain stub methods. In actual `add-device-audio` service's `AudioRecord` mixer (around source line 1358), separate NON_BLOCKING reads emit `max(micFrames,deviceFrames)` and zero-pad the other channel without retaining unmatched frames or aligning timestamps. Counterexample: reads `(960 mic, 0 device)` then `(0 mic, 960 device)` emit 1920 frames for one 960-frame source epoch, doubling time and separating simultaneous signals. This is a source algorithm failure, not an Android prohibition. | A common timestamp clock, pending per-source frames, drift/discontinuity policy and a stereo history/export path with adversarial delayed-read tests. Device-only capture already works independently. |
| Age-based multi-quality history/re-encoding | Mike master `AudioEncoder.encode` and `reEncode` throw `UnsupportedOperationException`; `isCodecSupported` returns false. Development branch `copilot/refactor-application-vsa-architecture` `db16409a73ff0b4db3b964bbd47446260f292ee8` does not supply a verified working ageing encoder path. Current fixed quality 32/64/96 kbps works. | Valid tier transitions and re-encoding with timestamps/sample cuts, accounting for temporary double storage and lossy generation changes, followed by independent output and resource tests. |

Source plans for silence skipping/effects/alternate architecture are not implemented source features. Amplitude saves and ordinary fixed quality replace usable activity/quality behavior. Wi-Fi/Bluetooth trigger rules in upstream #49 are an inventory item only; no complete usable implementation was found in the audited additions. Battery and schedule rules are implemented. Adding a general rule engine is not implied by those requests.
